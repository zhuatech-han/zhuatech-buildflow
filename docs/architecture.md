# 架构与业务边界

知华科技（上海如静知华信息科技有限公司） · https://www.zhuatech.cn/ · 商业授权、定制、部署与集成咨询微信：zhuatech / zhuatech2。

BuildFlow 是一个企业实例、多个部门、多个项目的工程管理系统。Java21 / Spring Boot4 / JPA 提供事务和安全边界；Vue3 以同源会话调用API；MySQL8.4 和 Flyway 保存版本化结构；Nginx仅代理前端及必要API。核心功能不依赖第三方服务。

项目是一切清单、工程量、合同变更、成本、结算和资金登记的聚合根。所有变更先锁项目行，比较客户端 revision，再写状态与审计；旧版本请求409，页面需刷新后重试。清单激活前可修改和删除，激活后单价、分包商被冻结，工程量和其他直接成本预算通过独立审批的增减项调整。

项目经理与财务按部门可见。现场ASSIGNED范围只看明确项目成员的工程及验收，不见单价、分包、成本和资金。客户只看绑定本人项目的合同单价、验收及客户结算单；不见分包或内部成本。API响应与下载也按上述规则过滤，不只隐藏菜单。

`project.read` 控制项目读取；`project.write` 控制合同；`site` 控制现场提交；`review` 独立验收及变更；`cost` 成本与结算申请；`finance` 成本及结算审核、登记资金及释放保留款；`report` 成本报告；`admin` 全范围系统管理；`audit` 审计。自定义角色仍由业务接口检查。客户绑定角色的权限不能扩大为内部岗位。最后有效管理员受保护。

申报人不能审核自己的工程量、增减项、成本或结算单。同一项目锁防止并发超申报/超结算；待审工程量占用剩余容量，退回后释放。客户/分包两个方向分别累计结算工程量，不能超过已验收量。每行结算量乘冻结单价并HALF_UP至两位，不能在客户端指定金额。金额使用BigDecimal，工程量最多四位、金额两位。

资金记录不实际转账。支付、关联退款、关联冲正保存原始行，不能覆盖或删除。requestKey与载荷SHA256指纹防重复提交；同一账号相同内容重试返回原记录，不同内容409。退款限原支付未退净额，冲正必须完整关联、金额一致且不破坏当前可收付余额。已有下游记录的原付款不可冲正，采用关联退款修正。

保留款比例由合同人工录入（0–100%），不预设法定比例。批准结算时冻结金额；合同工程量全部验收后，财务录入释放凭据才增加到期应收/应付。结清完工要求全量验收、所有非零单价工程量完成双向结算、无待审记录、全部保留款释放且所有批准账单余额为零。

已确认项目成本 = 已审核人工/材料/其他直接成本 + 已批准分包结算毛额。分包费用不可重复录入成本凭据。已确认毛利 = 已验收客户产值 − 已确认项目成本；计划毛利 = 批准合同额 − 其他预算及分包承诺。二者不是法定财务报表，也不包括企业间接费、税费或未入账事项。

没有ERP连接、BIM/CAD、在线支付、税务发票、电子签名、多币种换算、离线同步或法规合规声明。项目、客户及分包资料为人工录入，不声称任何外部身份认证。
